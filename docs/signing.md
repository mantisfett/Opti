# Подпись релиза

Без подписи кода Windows SmartScreen показывает предупреждение «Неопознанное приложение» при запуске `Opti.exe`. Сборка уже подготовлена к подписи: нужен только сертификат.

## Что нужно

Сертификат подписи кода (Code Signing) от удостоверяющего центра — файл `.pfx` с паролем. Обычные сертификаты (OV) подписывают, но SmartScreen доверяет им не сразу, а по мере накопления репутации; сертификаты EV доверяются сразу, но выдаются на организацию и часто хранятся на аппаратном ключе (его нельзя положить в секрет CI — для него нужна подпись на своей машине или облачная подпись). Покупать сертификат и хранить его — решение владельца проекта; Opti сам ничего не покупает и не получает.

## Подпись в CI (GitHub Actions)

1. Переведите `.pfx` в base64: в PowerShell `[Convert]::ToBase64String([IO.File]::ReadAllBytes('cert.pfx'))`.
2. В репозитории (Settings → Secrets and variables → Actions) добавьте секреты:
   - `OPTI_SIGN_CERT_BASE64` — строка base64;
   - `OPTI_SIGN_CERT_PASSWORD` — пароль сертификата.
3. Запустите релиз как обычно. `build/publish.ps1` подпишет `Opti.exe` и `opti-cli.exe` (SHA-256, метка времени DigiCert) **до** подсчёта `SHA256SUMS.txt` и проверит подпись командой `signtool verify /pa`. Если проверка не прошла, сборка падает.

Если секретов нет, релиз собирается неподписанным и не падает.

## Подпись на своей машине

```powershell
$env:OPTI_SIGN_CERT_BASE64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes('cert.pfx'))
$env:OPTI_SIGN_CERT_PASSWORD = '...'
powershell -ExecutionPolicy Bypass -File build\publish.ps1
```

Нужен Windows SDK (`signtool.exe`). Другой сервер меток времени — переменная `OPTI_SIGN_TIMESTAMP`.

## Что подписывается

Подписываются два файла: лаунчеры `Opti.exe` и `opti-cli.exe`. Приложение внутри них (zip-ресурс) снаружи не видно; SmartScreen и проводник проверяют именно внешний файл. После первого запуска приложение выкладывается в защищённую папку `C:\ProgramData\Opti\app`.

Проверка подписи у пользователя: ПКМ на файле → Свойства → «Цифровые подписи», либо `Get-AuthenticodeSignature Opti.exe`.

## Что проверено, а что нет

- Синтаксис `build/sign.ps1` и `build/publish.ps1` проверяется парсером PowerShell (локально и в CI).
- Логика `build/sign.ps1` проверена с поддельным `signtool`: аргументы (`/fd SHA256 /td SHA256 /tr … /f … /p …`), порядок «подписать → проверить» для каждого файла, падение при неудачной проверке, удаление временного `.pfx` в обоих случаях, понятные ошибки без сертификата и без `signtool`.
- **Не проверена** подпись настоящим сертификатом и настоящим `signtool.exe`: у разработки нет сертификата. Первый релиз с сертификатом стоит сначала собрать вручную (`workflow_dispatch`) и проверить `Get-AuthenticodeSignature` на скачанном `Opti.exe`.
